# Devlog — 2026-08-01 (session 11)

## What got built

A GitHub Actions CI workflow — the first of the two "next session candidates" from
2026-07-30-session10 that was still fully unaddressed: the eval harness and the full test suite
both existed and worked standalone, but nothing external actually invoked either of them.

- **`.github/workflows/ci.yml`** — runs on every push to `main` and every PR targeting `main`:
  checkout, JDK 21 (Temurin, with Maven dependency caching via `actions/setup-java`), then
  `./mvnw -B test`.
- **Scope decision: unit/integration tests only, not the eval harness.** The eval harness needs a
  real `ANTHROPIC_API_KEY` and makes real Claude calls per case — running it on every push would mean
  storing a live key as a GitHub secret and paying real API cost on every commit, for a project still
  at 10 eval cases. Discussed this explicitly rather than defaulting to "wire everything" — the
  harness stays a manual/local gate for now; CI gates on the 35 tests that already run fully
  self-contained (Testcontainers-managed Postgres and Kafka, no external services, no secrets).
  Revisit once the eval set is bigger and cost-per-run is worth budgeting for.
- **Why `./mvnw test` alone is sufficient as the CI command**: there's no Failsafe plugin in
  `pom.xml`, so Surefire's default `**/*Test.java` include pattern already picks up every test class
  — unit and Testcontainers-integration alike (`TriageKafkaIntegrationTest`,
  `HivemindApplicationTests` via `AbstractPostgresIntegrationTest`). One command, no separate
  `verify`/integration-test phase to wire up.
- **Verified locally before trusting it on a runner**: ran `./mvnw -B test` — the exact command in
  the workflow — end to end. 35/35 green, including the two Testcontainers classes (Postgres +
  Kafka containers spun up and torn down automatically). GitHub's `ubuntu-latest` runners ship Docker
  pre-installed, so no extra Testcontainers setup step is needed in the workflow itself.
